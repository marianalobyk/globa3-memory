Creative Radar Rules — Globa 3 Creative Radar

Use this file together with the core manual briefing workflow.

Creative Radar uses the same core gates:

* Run Manifest
* Repeat Control
* Evidence Index
* Draft
* QA
* Finalize
* Item Memory Updates

Creative Radar has brief-specific logic because it is not a standard business-unit operating brief.

Creative Radar is a daily creative-intelligence and scouting product.

It tracks:

* emerging talent
* projects
* story worlds
* artists
* filmmakers
* producers
* writers
* actors
* athletes moving into media
* musicians moving into screen IP
* visual artists and cultural figures entering media
* festival validation
* labs
* grants
* regional IP
* diaspora projects
* women-led stories
* sports-led stories
* youth / creator economy signals
* relationship targets
* newsletter themes
* institutional proof points

It must not become:

* celebrity news
* gossip
* generic entertainment news
* streaming guide
* review roundup
* culture newsletter
* social-media trend digest
* weekly scouting dossier
* source-log document

⸻

Clean Output Rule

Creative Radar follows the v3 Clean Output Split.

The reader-facing Creative Radar must not include:

* Run Manifest
* Run Metadata as a separate section
* Evidence Index
* Source cards
* full source tables
* full Sources section
* full Source Notes section
* QA notes
* Operator notes
* Item Memory updates
* Internal reasoning
* Prompt explanations
* Source IDs
* Archive instructions
* Filename instructions
* full production source logs
* audit-style source notes
* duplicate header block near the end

Evidence, source checks, QA results, source logs, repeat justifications, and memory updates must be kept as separate internal production files.

The reader-facing brief may include concise item-level source references only when useful to the reader.

Allowed reader-facing source references:

* Source: Deadline, 15 June 2026.
* Source quality: Strong Trade.
* External-use status: Internal only.

Forbidden reader-facing source formats:

* Sources
* numbered source list
* full source log
* source-card table
* Evidence Index table
* audit-style source notes
* internal verification notes
* production source logs
* source IDs
* source notes after Final Approval Status

If a full Sources section appears in the reader-facing Creative Radar, use:

REJECT — DO NOT SEND

If the title / header block repeats near the end of the brief, use:

REJECT — DO NOT SEND

Final Approval Status must be the final line.

Nothing may appear after Final Approval Status.

⸻

Daily Operating Model

Creative Radar runs daily, Monday to Friday.

Primary daily window:

* preceding 24 hours

Rolling context window:

* previous 7 days

Forward watch window:

* next 30 days

Urgent alerts:

* only for major items outside the daily cadence

Daily items must have a fresh trigger inside the daily window.

Rolling items may appear only in continuity sections and must not be presented as fresh.

Forward-looking items must have a clear upcoming date, deadline, festival, grant, release, market, lab, or event basis.

If the brief is run outside the standard delivery window:

* recalculate the coverage window from actual run time;
* state the actual coverage window in the reader-facing header;
* keep detailed run metadata internal.

Do not use weekly cadence language unless the run is explicitly a weekly run.

Do not let rolling context turn the daily brief into a weekly memo.

⸻

Section 1 Rule — Priority Creative Signals Today

Section 1 is the strictest section.

Target count:

* 0 to 3 items on normal days
* up to 5 items only on exceptional high-signal days

Only include items that have:

* fresh daily trigger
* traceable source
* visible or stated date
* Gulf / Africa / diaspora connection
* Globa 3 relevance
* clear creative, IP, talent, relationship, institutional, platform, or story-world value

If there are no qualifying items, write exactly:

No priority creative signal cleared the threshold today.

Do not pad Section 1.

Rolling context items must not appear in Section 1 unless they have a new material update today.

Do not move older items into Section 1 just because the daily window is thin.

A thin Section 1 is acceptable.

A padded Section 1 is not.

Hard rejects:

* old item presented as fresh
* rolling item presented as daily signal
* generic celebrity item
* review-only item
* weak-source item presented as settled fact
* item with no Globa 3 angle
* Section 1 padded to reach 3 items

⸻

Daily / Rolling Repetition Rule

Because Creative Radar runs daily, rolling 7-day items may repeat only when they add continuity value.

If an item appeared in a previous Creative Radar and has no new material development today:

* do not place it in Section 1 — Priority Creative Signals Today;
* do not describe it as fresh, new, emerging, newly validated, or newly announced;
* place it only in rolling-context sections if it still ranks among the strongest signals of the week;
* label it clearly as Rolling 7-day context / carried forward;
* add “No new update today” when useful.

Do not repeat the same item across multiple sections unless each placement adds a different operational use:

* talent mapping;
* project watch;
* institutional watch;
* newsletter theme;
* relationship target;
* rejected / not elevated.

If repetition adds no new decision value, remove the duplicate.

⸻

Repeat Compression Rule

Creative Radar must not become a repeated-item dossier.

Default allowed placements for one strong item:

1. one primary analytical section;
2. one operational section;
3. one weekly / theme / relationship section.

If the same item appears in more than 3 reader-facing sections, complete an internal Repeat Justification.

The Repeat Justification must explain:

* why each placement is necessary;
* what distinct operational function each placement serves;
* why compression would reduce usefulness;
* why the item is not simply being used to fill sections.

Do not print the Repeat Justification in the reader-facing brief.

If the same item appears in 4+ sections without internal justification, the maximum final status is:

PASS — INTERNAL ONLY

If repeated-item sprawl makes the brief functionally unreadable or weekly-style, use:

REJECT — DO NOT SEND

Examples of overuse:

* the same project appears in Executive Summary, Talent Radar, Projects & Story Worlds, Athlete / Artist / Creator-to-IP, Top Signals This Week, Relationship Targets, Projects to Watch, and Newsletter Themes;
* the same institutional programme is repeated across Section 1, Section 4, Section 6, Section 7, Section 8, and Section 9 with little new function;
* the same filmmaker is described as a discovery, project lead, relationship target, newsletter theme, and project watch without distinct operational value.

Compression is preferred.

⸻

Rolling Context Containment Rule

Rolling context is allowed, but it must not dominate the daily brief.

Items outside the daily window may appear in Executive Summary only if:

1. they have a forward deadline, event, or decision point inside the next 30 days; or
2. they are one of the top 2 strategic watch items in the rolling week; and
3. they are clearly labeled as rolling context, forward watch, or structural context; and
4. they do not crowd out fresh daily items.

Items outside the rolling 7-day window may appear only if:

* they have an upcoming deadline / event inside the forward watch window;
* they are necessary background to understand a fresh daily item;
* they are included in Rejected / Not Elevated as a reason not to elevate;
* they are explicitly labeled as outside rolling window.

Forbidden:

* old festival selection written as fresh;
* May / early-June programme used as a main daily item without upcoming deadline;
* outside-window item dominating Executive Summary without forward relevance;
* rolling-context item repeated across many sections without decision value;
* old item used to make a thin daily window look active.

If rolling context dominates more than half of the reader-facing brief, the maximum final status is:

PASS — INTERNAL ONLY

unless the run is explicitly a weekly / recap run.

If rolling context is presented as fresh, use:

REJECT — DO NOT SEND

⸻

Daily Compactness Rule

This is a daily radar, not a weekly report.

Prefer fewer, stronger items over full sections.

On normal days:

* Section 1 may contain 0–3 items.
* Section 2 should contain 3–5 people / teams.
* Section 3 should contain 3–5 projects.
* Section 4 should contain 2–4 institutional signals.
* Section 5 may contain 0–3 athlete / artist / creator-to-IP signals.
* Section 6 may contain up to 5 creative signals this week.
* Section 7 should contain 3–5 relationship targets.
* Section 8 should contain 3–5 projects.
* Section 9 should contain 3–5 newsletter themes.
* Section 10 should contain 3–6 rejected / not elevated items.

Use higher counts only on genuinely high-signal days.

Do not pad sections to hit target counts.

A thin day is acceptable.

A no-priority-signal day is acceptable.

Accuracy and usefulness matter more than volume.

If the brief is accurate but too bloated for daily operational use, the maximum final status is:

PASS — INTERNAL ONLY

If the brief becomes a weekly dossier while labeled as daily, use:

REJECT — DO NOT SEND

⸻

Creative Signal Threshold

A Creative Radar item must answer:

* Why this person?
* Why this project?
* Why now?
* Why Globa 3?

Include an item only if it has at least one of these:

* fresh project announcement
* festival selection
* award
* lab / fund / grant / market selection
* platform / broadcaster / streamer backing
* production start
* distribution / sales announcement
* credible trade profile
* athlete / artist / musician movement into media or IP
* creator-platform move
* regional IP signal
* relationship target value
* newsletter theme value
* institutional proof point
* forward deadline / event with clear Globa 3 relevance

Do not include an item only because the person is famous.

Do not elevate a project only because it was reviewed.

Do not elevate a cultural item unless it has talent, project, IP, institutional, platform, relationship, audience, or creative-economy relevance.

⸻

Source-to-Claim Rule

Every important claim must map to a source.

For each item, confirm:

1. Which source supports what happened?
2. Which source supports the date?
3. Which source supports the Gulf / Africa / diaspora connection?
4. Which source supports the role of the talent or project?
5. Which source supports any festival, fund, lab, market, platform, or institutional validation?
6. Which source supports the Globa 3 relevance claim?
7. Which source supports any award, selection, grant, funding, rights, production, screener, or relationship claim?
8. Which parts are analysis rather than reported fact?
9. Which parts are external-safe fact versus internal-only analysis?

If a claim cannot be mapped to a source:

* remove it;
* soften it;
* label it as analysis;
* move item to Verification required;
* or move item to Rejected / Not Elevated.

No URL = no confident claim.

URL present does not mean source is valid.

If source is placeholder, inaccessible, unrelated, or not checked:

* Verification required;
* or Reject.

Do not use broad source notes as substitute for exact claim support.

Do not use full source logs in the reader-facing brief.

⸻

Source Quality Rule

Use exactly one source-quality label for each item:

* Official / Primary
* Strong Trade
* Credible Secondary
* Needs Verification

Official / Primary

Official festival, fund, lab, market, institution, platform, broadcaster, production company, artist, athlete, creator, or film commission source.

Strong Trade

Recognized industry trade or business publication with direct reporting.

Examples:

* Variety
* Deadline
* The Hollywood Reporter
* Screen Daily / Screen International
* IndieWire
* Broadcast
* C21
* TBI
* Kidscreen, if relevant
* Music Business Worldwide
* Billboard, where relevant
* World Screen
* Cineuropa
* Film New Europe, where relevant

Credible Secondary

Reliable regional or cultural reporting that is not the primary source.

Needs Verification

Insufficiently confirmed, social-first, weak, incomplete, or not externally safe.

Do not use Needs Verification items as settled facts.

Do not use social media as the sole source for external-safe items unless the account is official and the claim is straightforward.

Source quality must match language confidence.

If source quality is weak, possible action and external-use status must be conservative.

⸻

External-Safe vs Internal-Only Rule

Separate external-safe facts from internal-only analysis.

A sourced fact may be safe for external use.

But the following are usually internal-only unless directly sourced:

* relationship priority
* talent database priority
* strategic node
* access path
* rights opportunity
* screener opportunity
* Globa 3 opportunity
* partner angle
* commercial relevance
* contact path
* producer / sales path beyond what source says

Example:

External-safe fact:

* The project won an award at a festival.

Internal-only analysis:

* The director should be added to Globa 3’s relationship map.

Do not mark speculative relationship, screener, rights, access, contact, or strategy analysis as Safe for external newsletter.

⸻

External / Internal Split Rule

External-use status must be exactly one of:

* Safe for external newsletter
* Internal only
* Verification required

Do not combine statuses in one field.

Forbidden:

* Safe for external newsletter / Internal only
* Safe externally for facts; internal for analysis
* Safe fact-only; internal relationship mapping
* Internal but external for facts
* Safe except relationship analysis
* Safe for external newsletter (fact-only); Internal only (relationship mapping)

If the fact is externally safe but the Globa 3 analysis is internal, use:

External-use status: Internal only

Then add optional fields:

External-safe facts:
[Short fact-only wording that could be used externally.]

Internal-only analysis:
[Relationship, strategy, screener, rights, contact, commercial, Globa 3 path, or other internal interpretation.]

Do not mark speculative relationship value as Safe for external newsletter.

Do not mark relationship mapping, talent database priority, screener path, rights path, contact path, or Globa 3 opportunity as externally safe unless directly sourced.

If mixed status appears, fix before final.

Multiple mixed-status items cap the guide at:

PASS — INTERNAL ONLY

until corrected.

⸻

Relationship Target Discipline

Relationship Targets must have:

* a person, team, company, institution, festival, fund, lab, platform, or production entity;
* a source-controlled reason to track;
* a plausible Globa 3 relevance label;
* a realistic action.

Allowed actions:

* Map relationship
* Add to talent database
* Request screener
* Watch
* Verify
* Include in weekly themes
* Explore partner angle
* No action yet
* Contact, only when justified by source confidence and action strength

Do not use vague actions:

* monitor
* keep an eye on
* stay close
* follow up someday

Do not imply Globa 3 already has access, rights, contact, screener, or relationship unless sourced.

Relationship Map means:

* internally map this person / institution / company / project

It does not mean:

* Globa 3 has an existing relationship
* outreach is ready
* access exists
* rights are available

⸻

Relationship Action Escalation Rule

Possible actions must match evidence confidence.

Use Contact only when:

* the item is source-controlled;
* the person / entity is clearly identifiable;
* the opportunity is strong enough to justify outreach;
* the relationship path is not invented;
* the action is proportionate to the signal.

Use Request screener only when:

* the project exists as a completed or screened work; or
* it has public festival / market / sales path suggesting a screener may plausibly exist;
* the project party is identifiable;
* the action does not imply Globa 3 already has access.

Use Explore partner angle only when:

* the possible partner or institution is identifiable;
* the item creates a plausible strategic path;
* the action is framed as exploration, not existing relationship.

Use Map relationship when:

* the person or institution is relevant but no direct access path is known;
* the item is useful for internal relationship intelligence;
* outreach would be premature.

Use Verify when:

* source quality is weak;
* rights / attachment / contact / screener / project status is unclear;
* the signal is promising but not yet actionable.

Forbidden:

* Contact based only on weak source or vague relevance;
* Request screener for a project with no evidence of completion, screening, festival, sales, or distribution path;
* Explore partner angle where the partner relationship is speculative;
* action language implying Globa 3 already has access, rights, screener, contact, or relationship.

If an action overreaches source confidence, downgrade it.

Action overreach blocks PASS — SAFE TO SEND.

⸻

Athlete / Artist / Creator-to-IP Discipline

Athlete, artist, musician, or creator items must involve real movement into:

* media
* film
* documentary
* scripted content
* podcast
* branded content
* platform
* production company
* rights
* distribution
* story-world development
* audience / community / IP product

Do not include:

* generic sports results
* generic music releases
* exhibition news without media / IP path
* social virality
* celebrity posts
* fan speculation

If there is no media / IP movement, reject or keep out.

If the item is promising but source base is weak, use:

Verification required

or:

Internal only

Do not use Athlete-to-IP or Artist-to-IP classification just because the person is famous.

⸻

Festival / Lab / Fund Discipline

Festival, lab, fund, grant, and market items can be elevated only when:

* the project or talent has Gulf / Africa / diaspora relevance;
* the selection / award / grant / market status is directly sourced;
* the date is clear;
* the item creates scouting, relationship, Studios, Advisory, Ventures, AMV, AFC, Unseen Arabia, or newsletter value.

Do not overclaim:

* international validation
* breakout status
* production readiness
* distribution prospects
* funding security
* rights availability
* commercial path
* relationship access

unless source directly supports it.

If selection / award / funding status is vague, verify or reject.

⸻

Institutional / Incentive Live-Status Hard Gate

Any claim that an incentive, rebate, grant, fund, lab, application, committee, market, programme, call, or institutional mechanism is:

* live
* open
* active
* accepting applications
* confirmed live
* launched
* available
* operational
* in force
* administering applications
* ready for applicants

must be supported by an official current source.

Official current source means one of:

* official institution website
* official application form
* official guidelines page
* official call-for-applications page
* official programme page
* official film commission / fund / market / lab page
* official dated announcement from the administering body

Trade coverage may support launch context, announcement date, partners, or expected timing.

Trade coverage does not by itself prove current operational status unless it directly quotes or links to current official application mechanics.

Do not use “live,” “open,” “active,” “accepting applications,” “confirmed live,” “operational,” or “available” based only on:

* launch announcement
* trade preview
* old press release
* “expected from Q2”
* “will open”
* “planned to open”
* “set to open”
* “expected guidelines”
* secondary coverage without official application page

If official current source is not checked, use:

“Application status and mechanics require direct verification with the administering body before external use.”

or:

“Announced with applications expected from [date/quarter]; verify current application status before using as operational intelligence.”

For institutional / incentive items, separate:

External-safe fact:
[What the source directly confirms.]

Internal-only analysis:
[Why Globa 3 should map it.]

Do not place institutional incentive mechanics in Relationship Targets unless the relationship path is clear and the live-status claim is source-controlled.

If the item is useful but current operational status is not fully verified, possible action must be:

Verify

or:

Map relationship / Verify

Do not use:

Contact

or:

Explore partner angle

until the institutional status and relationship path are source-controlled.

If live-status wording is unsupported, maximum final status is:

PASS — INTERNAL ONLY — REFRESH REQUIRED

If unsupported live-status wording is central to the item and remains uncorrected, use:

REJECT — DO NOT SEND

⸻

Festival Awards Overstatement Rule

Festival validation is valuable, but award language must be proportionate.

Do not use:

* swept
* dominated
* landmark
* breakout
* historic
* unprecedented
* major moment
* first-ever
* definitive
* proved
* took over
* exploded
* transformed

unless the source directly supports the scale of that claim.

Prefer:

* won multiple awards
* received festival validation
* converted selection into awards
* won across several categories
* strong festival validation
* notable awards showing
* significant regional validation
* one of the strongest regional signals this week

Example:

Do not write:

Three African films swept Tribeca 2026.

unless the source explicitly frames it as a sweep.

Prefer:

Three African films won major Tribeca prizes in 2026.

or:

African films converted Tribeca selection into multiple awards.

Unsupported festival overstatement blocks PASS — SAFE TO SEND.

Unsupported historic / first-ever / landmark claim may trigger:

REJECT — DO NOT SEND

if central to the item.

⸻

Newsletter Theme Discipline

Possible Newsletter Themes must be grounded in items inside the brief.

Do not invent themes from general knowledge.

A valid theme must connect at least two of:

* source-supported item
* Gulf / Africa / diaspora angle
* talent / project / IP signal
* cultural or creative-economy pattern
* Globa 3 relevance

If the theme cannot be traced to brief items, remove it.

If the theme is based on a repeated rolling item, it must add a distinct editorial angle.

If the theme is based on a rejected item, explain why it is only context, not elevated signal.

⸻

Rejected / Not Elevated Discipline

Rejected / Not Elevated must prove selection discipline.

Each rejected item should include:

* item
* reason rejected
* source status
* whether to ignore, watch, or verify later

Common reject reasons:

* celebrity-only
* gossip
* no Gulf / Africa / diaspora tie
* no Globa 3 angle
* weak source
* no URL
* social-only
* old item
* review-only
* generic Hollywood
* no action value
* already covered with no new trigger
* summary-context only, not enough standalone information to elevate

Rejected items must not appear in elevated sections unless reclassified in the Evidence Index first.

If an item appears in Executive Summary as group context but is rejected as a standalone item, state:

summary-context only; not enough standalone information to elevate.

Reject if:

* rejected item is stronger than elevated items;
* rejected item contradicts Executive Summary;
* rejected item is actually elevated elsewhere without explanation.

⸻

Final Approval Discipline

Use:

PASS — SAFE TO SEND

only if:

* all Executive Summary items are source-controlled;
* all external-facing claims are safe;
* source quality labels are accurate;
* external-use status labels are exact and not mixed;
* no Needs Verification item is presented as fact;
* no social-only or weak-source item is external-safe;
* no old item is presented as fresh;
* no rolling context is misrepresented as daily signal;
* no speculative relationship / rights / access / screener / contact claim appears externally safe;
* all actions are proportionate to source quality;
* repeated items are compressed or justified internally;
* no full Sources section appears;
* no duplicate header / export artifact appears;
* festival award language is proportionate and source-supported;
* Source-to-Claim QA is complete.

If Run Manifest says External Send Allowed: No, the maximum final status is:

PASS — INTERNAL ONLY

Even if the draft itself passes all source and structure checks.

Controlled-test URLs, placeholder URLs, or URLs marked “test-valid” are acceptable for testing workflow logic only.

They must not support PASS — SAFE TO SEND in a real or simulated final status.

Use:

PASS — INTERNAL ONLY

when:

* the brief is useful for internal scouting;
* relationship, rights, screener, contact, or source confidence requires caution;
* some analysis is strategic but not external-safe;
* rolling context is useful but too dominant for external send;
* repeated items require compression;
* source support is useful but not external-safe.

Use:

PASS — INTERNAL ONLY — REFRESH REQUIRED

when:

* one or more high-value items require same-day source refresh;
* source status is close to safe but needs confirmation;
* a festival, lab, grant, market, platform, or deadline item may have changed;
* external send would require rechecking current status.

Use:

REJECT — DO NOT SEND

when:

* hard QA failures remain;
* unsupported claims are central;
* structure is broken;
* old items are presented as fresh;
* rolling context is presented as daily signal;
* weak-source material is elevated;
* celebrity / culture noise dominates;
* sources are missing;
* a full Sources section appears;
* duplicate header / export artifact appears;
* repeated-item sprawl makes the brief unusable;
* Final Approval Status would be misleading.

⸻

Final Output Rule

The reader-facing Creative Radar must end with exactly one of:

PASS — SAFE TO SEND

PASS — INTERNAL ONLY

PASS — INTERNAL ONLY — REFRESH REQUIRED

REJECT — DO NOT SEND

Final Approval Status must be the final line.

Nothing may appear after it.

Forbidden after Final Approval Status:

* sources
* notes
* metadata
* duplicate header
* source links
* explanation
* archive text
* QA text
* memory text

If anything appears after Final Approval Status, use:

REJECT — DO NOT SEND

Quality Standard

The Creative Radar may proceed only if:

* the structure is correct;
* clean output rules pass;
* daily and rolling context are separated;
* Section 1 has only fresh daily triggers or no priority signal statement;
* every elevated item has a source-controlled creative signal;
* every elevated item has Gulf / Africa / diaspora or Globa 3 relevance;
* every item has correct classification;
* every item has source quality;
* every item has exact external-use status;
* every item has proportionate possible action;
* repeated items are compressed or justified;
* relationship targets have a reason and path;
* project items have story-world or IP value;
* athlete / artist / creator-to-IP items involve real movement into media or IP;
* newsletter themes are grounded in brief items;
* Rejected / Not Elevated proves selection discipline;
* no celebrity, gossip, social-only, or generic culture items are elevated;
* no old items are presented as fresh;
* no source-to-claim gaps remain;
* no full Sources section appears;
* no duplicate header appears near the end;
* PASS — SAFE TO SEND is used only when fully earned;
* Final Approval Status is the final line.

If any hard test fails, enter Fix Loop.
