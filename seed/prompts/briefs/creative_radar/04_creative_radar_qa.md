A. Structure and Clean Output

Confirm the Creative Radar follows the required structure exactly.

* Title is correct: Globa 3 Creative Radar.
* Date is present and correct.
* Priority geography is stated: Gulf, Africa, diaspora.
* Coverage window is stated explicitly.
* Rolling context window is stated explicitly.
* Executive Summary is present.
* All required sections are present in the correct order:
    1. Priority Creative Signals Today
    2. Talent & Relationship Radar
    3. Projects & Story Worlds to Watch
    4. Institutional / Festival / Funding Signals
    5. Athlete / Artist / Creator-to-IP Watch

    7. Relationship Targets

    * PASS — SAFE TO SEND
    * PASS — INTERNAL ONLY

D. Coverage Window / Daily vs Rolling Context Check

The Creative Radar is a daily brief.

Primary daily window:

* preceding 24 hours

Rolling context window:

* previous 7 days

Forward watch window:

* next 30 days

Confirm:

* Section 1 — Priority Creative Signals Today includes only same-window daily items, unless clearly marked as no priority signal.
* Primary daily items have a fresh trigger inside the preceding 24 hours.
* Rolling 7-day items are used only in rolling / continuity sections.
* Rolling 7-day items are not presented as fresh daily items.
* Items outside the rolling 7-day window appear only if they have a forward deadline / event inside the next 30 days, are necessary background to understand a fresh item, or are explicitly rejected.
* Forward-looking items have confirmed upcoming timing or a clear source basis.
* The brief does not call itself weekly.
* The brief does not use weekly cadence language.
* “Top Creative Signals This Week” is treated as a rolling 7-day section updated daily, not a weekly-only output.
* Carried-forward rolling items include “No new update today” where needed.
* Rolling context does not dominate more than half of the reader-facing brief unless the run is explicitly a weekly / recap run.

[REJECT] if a rolling 7-day item is presented as a fresh daily signal.

[REJECT] if the brief describes itself as weekly rather than daily.

[REJECT] if carried-forward rolling items make the brief feel like a recycled weekly memo rather than a daily radar.

[REJECT] if an old festival selection, fund award, project announcement, interview, or article is presented as fresh because it appeared in search results today.

[REJECT] if the coverage window is missing, vague, or inconsistent with run time.

[REJECT] if an outside-window item dominates Executive Summary without forward relevance or label.

H. Source-to-Claim QA Test

For every Executive Summary item, top-section item, relationship target, project-to-watch item, possible action, newsletter theme, rejected-context item, and Final Approval Status claim:

1. Identify the exact source that supports it.
2. Confirm the source supports the exact wording used.
3. Confirm source confidence matches the language.
4. Confirm unsupported interpretation is labeled as analysis.
5. Confirm no Needs Verification item is presented as settled fact.
6. Confirm any external-safe fact is separated from internal-only Globa 3 interpretation.

Apply this test to:

* Executive Summary bullets.
* Priority Creative Signals Today.
* Talent & Relationship Radar.
* Projects & Story Worlds to Watch.
* Institutional / Festival / Funding Signals.
* Athlete / Artist / Creator-to-IP Watch.
* Top Creative Signals This Week.
* Relationship Targets.
* Projects to Watch.
* Possible Newsletter Themes.
* Rejected / Not Elevated.
* Final Approval Status.
* Any claim that affects external-use safety.

Confirm:

* Every important claim maps to a specific source.
* The source supports the exact wording, not merely the broad topic.
* The source is strong enough for the confidence level used.
* Source limits are visible where needed.
* Any interpretation is labeled as analysis, not reported fact.
* No Needs Verification item is treated as settled.
* No social-only claim is treated as externally safe.
* No broad source note is used as a substitute for exact claim support.
* Final Approval Status matches the real source confidence.

[REJECT] if any important claim cannot be mapped to a source.

[REJECT] if the source does not support the exact wording used.

[REJECT] if source confidence does not match the language.

[REJECT] if unsupported interpretation is written as reported fact.

[REJECT] if a Needs Verification item is presented as settled fact.

[REJECT] if Final Approval Status claims the brief is safe to send while any major source-to-claim gap remains.

J. External / Internal Status QA

Every item must have exactly one External-use status:

* Safe for external newsletter
* Internal only
* Verification required

Forbidden External-use status formats:

* Safe for external newsletter / Internal only
* Safe externally for facts; internal for analysis
* Safe fact-only; internal relationship mapping
* Internal but external for facts
* Safe except relationship analysis
* Safe for external newsletter (fact-only); Internal only (relationship mapping)

If facts are externally safe but analysis is internal, the item should use:

External-use status: Internal only

Then optional fields may appear:

External-safe facts:
[Fact-only wording.]

Internal-only analysis:
[Relationship / strategy / screener / rights / Globa 3 interpretation.]

Confirm:

* External-use status is exactly one allowed value.
* Safe for external newsletter is used only when source is Official / Primary or Strong Trade.

* Safe for external newsletter does not include speculative relationship, rights, screener, contact, access, or Globa 3 opportunity claims.

* Verification required is used when source base is weak, social-first, unclear, incomplete, or not externally safe.

[REJECT] if a Needs Verification item is marked Safe for external newsletter.

[REJECT] if a weak, social-only, or incomplete item is marked externally safe.

[REJECT] if external-use status is missing.

[REJECT] if combined / mixed external-use status appears in multiple items and remains unfixed.

[REJECT] if speculative relationship analysis is marked Safe for external newsletter.

* No rights availability is assumed.
* No talent attachment is assumed without source support.
* No screener availability is assumed.
* No funding, development, production, or sales status is assumed.

* Contact
* Map relationship
* Request screener
* Add to talent database
* Include in weekly themes
* Explore partner angle
* Verify

* Explore partner angle is used only when partner path is plausible and not written as existing relationship.
* Map relationship is used where relevance is clear but access path is unknown.

[REJECT] if the brief recommends outreach or external use based on weak or incomplete information without verification.

[REJECT] if Contact is recommended from weak source only.

[REJECT] if Request screener is recommended when no screener / festival / market / sales / public screening path is plausible.

[REJECT] if Possible Action is vague.

[REJECT] if the action is “monitor,” “keep an eye on,” “stay close,” “follow up someday,” or equivalent.

[REJECT] if action overreaches source quality.
